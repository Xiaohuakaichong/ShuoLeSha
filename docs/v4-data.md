# 数据迁移与备份

结构 6 保留旧 `audio_records` 作为分片元数据，同时新增会话、不可覆盖原稿、FTS、话题、笔记、复盘、任务和处理队列。旧记录 ID、音频路径、完成状态保留；旧的每日复盘行转为独立复盘对象。

每次结构升级（当前目标结构 8）前，先在应用内部 `files/backups/pre-v<目标结构>/`（现为 `pre-v8/`）复制 `shuolesa_db`、存在的 `-wal` 和 `-shm`，最后写入 `complete` 标记。4.1.1 之前只在从 3、4、5 升级时备份到 `pre-v6/`，6 升 7 没有副本。备份不完整时下次重试覆盖不完整副本。未知数据库结构迁移失败，不清库、不删除音频。

`_v32_refactor` 的旧 v5 包没有被覆盖或自动安装。不要把同结构版本但字段不同的数据库混入现有记忆库。

“设置 → 数据与诊断 → 导出记忆库和原音备份”生成 ZIP。先停止录音；备份序列化处理任务和文件清理，Room 写事务期间复制稳定的数据库与 WAL，然后归档原音。导出内容：

- `database/shuolesa_db` 和存在的 `shuolesa_db-wal`。
- `files/` 下当前会话关联的原音与导入原件。
- `manifest.json`，注明结构版本、生成时间和原 files 根路径。

不含服务密钥、偏好文件或诊断日志。正在录音时拒绝完整备份。系统云备份排除记忆库和原音；设备迁移保留数据，但排除加密凭据和日志。

ZIP 当前用于完整数据保全与开发恢复，不提供覆盖现有记忆库的导入按钮。恢复需先停止应用，数据库与 WAL 一起放回应用数据库目录；跨路径恢复需依据 manifest 将数据库中的原 files 根路径映射为目标路径。应先保留目标库副本，不能用旧版 APK直接打开结构 6。没有设备数据访问权限时，使用 Android 的设备迁移或保留备份待开发恢复。

重试不会覆盖已有原稿。重新整理替换当前候选事项，已确认、完成或忽略事项按文本与来源匹配保留。旧版缺少明确待办原话时，保留该事项但不虚构引用。
